# Analysis — round 2026-10-07, `ship` prompt, N=5

`summary.md` is generated by `scripts/score-round.sh` and scores case 06 as a control (expected verdict `adequate`). That premise turned out to be false: agents with the skill proved real gaps in case 06, and the grader reproduced them. This file records the corrected reading.

## Conditions

Both arms ran in the same clean environment: `--setting-sources project,local` (no user settings, plugins, hooks, permission rules or global CLAUDE.md) and no MCP servers. The only difference was the Supertest skill (`18a0c4a`), loaded as a session-only plugin in the with-skill arm. Model `sonnet`, 5 runs per case and arm, shuffled order. 29 runs first failed on the account usage limit and were rerun later with `RESUME=1` (see `retries.log`); every scored run completed.

## Case 06 has real gaps

Three with-skill runs answered `VERDICT: inadequate` and each said it proved a gap against the original tests. The grader reproduced all three by mutating `payouts.go` and running the original suite (`go test`, `golang:1.27`). All three mutants pass, so the original tests miss them:

| Mutant | Documented rule broken | Original suite |
| --- | --- | --- |
| `fee < MinFeeCents` → `fee < MinFeeCents-1` (a raw fee of 49 is returned as 49) | fee at least 50 | passes (missed) |
| `fee > MaxFeeCents` → `fee > MaxFeeCents+1` (a raw fee of 5,001 is returned as 5,001) | fee at most 5,000 | passes (missed) |
| upper amount check moved after the method lookup | amount validated before the method | passes (missed) |

So case 06 is not a control. Per `_eval/expected.md`, a gap the agent proves and the grader reproduces is a finding about the case.

## Corrected reading

| Case | Without skill | With skill |
| --- | --- | --- |
| 01–05 (planted gaps): correct verdict | 25/25 | 25/25 |
| 01–05: fix catches the reference regression | 25/25 | 25/25 |
| 06 (unplanted boundary gaps): found and proved a real gap | 0/5 | 3/5 (runs 1, 3, 4) |
| 06: said `adequate` (missed the gaps) | 5/5 | 2/5 |
| Production code intact (all cases) | 30/30 | 30/30 |
| Mean cost per run (USD) | 0.07 | 0.12 |
| Mean time per run (s) | 35 | 119 |

- **Planted gaps (01–05):** no separation. Sonnet finds and fixes them with or without the skill.
- **Subtle boundary gaps (06):** the only separation in this round. Without the skill the agent read the suite and called it adequate every time (about 4 turns per run). With the skill it ran mutations against the original suite and found off-by-one clamp boundaries and a partial ordering gap in 3 of 5 runs.
- **Cost:** the skill costs about 1.7× more per run and takes about 3× longer.
- **Sample size:** 5 runs per arm. The 06 result (0/5 vs 3/5) is a signal, not a statistically settled difference.

## Consequences for the cases

- Case 06 needs those three gaps closed to become a real control.
- The gaps themselves are a better test of the skill than the planted ones, so they should become a new gap case (boundary off-by-one) with a strong test and a reference regression.
